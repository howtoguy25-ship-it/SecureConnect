Rebuild my app backend using Firebase as the primary backend and implement real Signal-style end-to-end encrypted direct messaging.

Main goal:
Create a production-grade backend and messaging system where private direct messages are end-to-end encrypted. Only the sender and recipient devices can read message contents. Firebase and the server must never be able to decrypt plaintext direct messages.

Critical truth requirements:
- Do not fake encryption
- Do not simulate encryption in UI only
- Do not use one shared hardcoded app-wide key
- Do not invent custom cryptographic algorithms
- Do not send private encryption keys to Firebase or any backend
- Do not store plaintext direct messages in Firestore, Realtime Database, logs, analytics, or admin tools
- Do not mark a chat as encrypted unless true E2EE is active

Architecture choice:
Use Firebase for:
- Authentication
- Firestore or Realtime Database for app data
- Cloud Functions for server logic where needed
- Cloud Storage for media storage
- FCM for notifications
- App Check where possible
- Security Rules for strict access control

Use Signal-style messaging concepts for encrypted direct messages:
- per-device identity key pair
- signed prekeys
- one-time prekeys
- secure session establishment using a reputable Signal-style protocol/library
- per-message ratcheting / fresh message keys
- forward secrecy where supported

Do not build homemade crypto.
Use a reputable maintained library if available for the client platforms being used.

Project requirement:
This must be a real implementation, not sample code, not pseudo-code, and not mock architecture.
Keep the rest of the app stable while upgrading messaging security.

Direct messaging security requirements:
Build encrypted 1-to-1 messaging with these rules:
- Generate identity key pairs on the client/device only
- Generate signed prekeys on the client/device only
- Generate one-time prekeys on the client/device only
- Upload only public key material to Firebase
- On first secure message:
  - fetch recipient prekey bundle
  - establish secure session locally
  - encrypt outgoing message locally
- On receiving:
  - decrypt message only on recipient device
- On later messages:
  - use ratcheting session state for fresh keys
- Support safe retries and duplicate protection
- Structure code to support future safety number / fingerprint verification

Private keys and session state:
- Store all private identity keys locally only
- Store session ratchet state locally only
- Use secure device storage where available
- Never sync private keys to Firebase in plaintext
- Never expose private keys to Cloud Functions
- Detect corrupt or missing session state and force secure session reset when needed
